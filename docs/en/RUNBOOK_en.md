5. Start the DAQ stack: `daq_up.sh` (root_sink → monitor → graw_writer → decoder → receiver → ECC → bridge → controller).

## 3. Run procedure (standard set)
| Order | Run type | config_id / preset | What to check |
|---|---|---|---|
| 1 | pedestal (internal periodically) | `pedestal` (`[TODO actual id]`) | per-ch baseline/noise → `calib pedestal` (081) |
| 2 | pulser (built into AsAd, amplitude ramp if needed) | `pulser` | relative gain → `calib pulser` (081), FPN saturation is normal |
| 3 | physics (external trigger) | `physics-<condition>` | visual checks in §4 below |
- **Pre-run check (the loop of 072 §4)**: (1) in the event display, tracks are not cut off at the window edge; (2) several tens of cells of pre-trigger baseline remain (allocation of delay — the formula of 080 §0: band position = (window − delay − L)/40 ns); (3) pressure, HV and flow are being recorded.
- The run number is assigned by the controller. **Overwriting an existing run is impossible by design** (countermeasure for the p.204 incident).
- When you change conditions, comment in the logbook (UI Logbook tab). **A run for which you did not write what was changed will be discarded in analysis**.

### 3.1 Parameters (UI Parameters tab, SPEC §3.3 — 078)
- Do not edit xcfg by hand. **Change knobs in the Parameters tab and Save**, which generates `configure-<id>.xcfg` / `prepare-<id>.xcfg`; the next run/start prepares / configures with that `<id>` (describe does not change). The `<id>` is kept in the logbook's `run_start.params` and in the audit.
- Commonly used knob = `triggerDelay` (in units of 10 ns). Experiment-switch level = `writingClockFrequency_MHz` / `gain` / `peakingTime_ns`, run type = `triggerMode` / `readout`, calibration = `pulser.*` / `globalThreshold` / `lsbThreshold`. **Setting `readout = partial` changes the frameType to 1** (inform the analysis side).
- To change only specific ch (e.g. the threshold of a noisy ch), add a row to **Exceptions**. The count is always shown in the status bar as `exceptions N` — **if you go into a physics run with N ≠ 0, write the reason in the logbook**.
- Save requires the control token (acquire it in Run control). It cannot be saved while Running (change it before the next run).
- **Caution**: as long as saved params (`current.json`) exist, **params take priority over the TOML config_id** (switching the run type in the TOML has no effect). When changing the run type, change Parameters, or check that `params <id>` in the status bar is the intended template (on 2026-09-23 an incident occurred where a "physics" run was started with the pulser settings still in place).
- The templates are the canonical xcfg in the ECC config repo (`ecc_config_dir`). When a new xcfg arrives from Warsaw, place it in the repo, change the template name in Parameters, and Save again (do not change the JSON).

## 4. What to monitor (UI)
- status: receiver `overflow_frames` / `extra_connections`, decoder `malformed`, graw-writer `write_errors`, root-sink
  `events_incomplete` — **all 0 is normal**. If any increases, see §5.
- Window-edge clip rate (after B-4 is implemented).
- **Slow control tab (079 / 089)**: latest values and trends (30 min) of gas pressure and flow (Bronkhorst), temperature and humidity (Arduino), HV VMON / IMON / STATUS (HiVolta), and AsAd LV (HMP2020). `slow` in the status bar = number of items in ALARM, **0 is normal**. `—` means slowctl is not running or the monitor's `slow_sub` is not set.
  If `poll_err` / `identity_mismatch` in `counters` keep increasing, wiring or by-id is mixed up (§5). **Instruments cannot be operated from this tab** (SPEC §11 — operation is done in the instrument-side GUI).
- ALARM does not stop the DAQ (default). ALARM / RECOVER of `slow` are recorded automatically in the logbook.
  **Periodic values are not written to the logbook** (only the values at run start and stop go into `run_start` / `run_stop`). All samples are in InfluxDB (`http://<host>:8086`, Data Explorer, bucket `slowctl`) — 122.
  The table is instrument × ch (Vmon / Vset / Imon / Iset / Status / ON/OFF). UNV of HV ch0 is a known behavior ("pulled by other ch"), so it is excluded from alarms (`ON UNV` appears in the Status column, 121).
- **When you connect an instrument (USB / power supply / measuring device) near the detector, compare the trigger rate before and after connecting**. With one bad USB cable, merely opening the HV power supply's port produced spurious triggers at 24–54 Hz (2026-10-12, 118).
- Most rate spikes come from the beam (SURVEY §4). Contact the control room.

## 5. Recovery
| Symptom | Remedy |
|---|---|
| zCoBo does not answer ping / ECC is at `WHEN_DESCRIBE` | `ssh root@192.168.4.8x`, `cd /etc/init.d; ./S99gethwserver stop; ./S99gethwserver start` (SURVEY p.230). If that fails, power-cycle (§1-2) |
| ECC appears to be Off/halt (`onUnPrepare` / breakup failure, `ecc_error: WHEN_BREAKUP`) | **It does not recover with the controller's reset (stays Off — measured in 069 #14) → restart getEccServer**. The Rust bridge reconnects automatically on the next operation, so just run/start (walk-back starts from Idle) |
| zCoBo's getHwServer died / board restart | The run ends naturally with `forced_eos:false` (receive EOF). run/stop waits 60 s for the ECC stop and ends with `abort:ecc-stop-failed`, but the received data is intact. On the board, `cd /etc/init.d && ./S99gethwserver start` (46001 comes back in 2 s) → restart ECC → run/start. The zCoBo ssh host key changes on every boot (by design), so use `StrictHostKeyChecking=no` |
| No data arrives or it stops (control works) | Suspect the jumbo-frame path: `ping -M do -s 8972` (073 #15). Check for `CoBo connected` in the receiver log |
| `extra_connections > 0` | Extra TCP connection (old dataRouter / another PC). Stop the other end before the run |
| Power outage / UPS discharge | Redo from the sequence in §1. A corrupted last line of the logbook is tolerated (§9.1) — the reader warns |
| HV TRIP | The DAQ is not stopped (default). Check the cause on the HV side (CAEN GUI) before recovering. A `slow` ALARM (trip bit of STATUS) is recorded automatically in the logbook |
| Slow control shows `—` / IDENT does not appear | Check the `slowctl` process and the TOML `port` (`/dev/serial/by-id/`). If `identity_mismatch` increases, a different instrument is being read (re-check by-id after swapping cables) |
| Parameters Save returns 503 | The controller's TOML has no `ecc_config_dir`. 409 = Running, 400 = value out of range (fix as the message says) |

## 6. Logbook conventions
- run_start/run_stop are automatic. What a person writes is a **comment**: condition changes, anomalies, beam state, source insertion/removal.
- Pressure, HV, flow, temperature and humidity are recorded automatically by slowctl (`slow` records: IDENT / VALUE / ALARM / RECOVER / ERROR, latest values in run_start / run_stop).
  For runs without slowctl running, **write the numbers in a comment at run start**.
- Parameters can be traced via `run_start.params.id`. For runs that used Exceptions, give the reason in a comment.

## When changing the HV values (CAEN GECO2020, 2026-10-15, archive/145)
1. `daq_down.sh` (because slowctl uses the same USB port `/dev/ttyACM0`).
2. On the desktop, `caengeco2020` (on Wayland, first `xhost +SI:localuser:daq`; autostart is set up). Connection: **SMART HV / VCP USB / Port `ttyACM0` (without `/dev/`) / 9600 / LBus 0**. The unit is in REMOTE.
3. After setting, close GECO (otherwise the port is contended). The leftover `/dev/shm/CAENV_LCK_0_0` may be deleted.
4. `daq_up.sh`. The next run_start.slow records the new values. There is no path to change voltage values from the web (SPEC §11).
5. **The first run/start right after power-cycling the LV (AsAd) may fail at configure (AGET register readback is 0)** — just run/start again (archive/149, 2026-10-15). If the LV stays OFF, prepare stops with "AsAd is disconnected from the power supply" (a normal rejection).

## ZS operation (zero suppression, 2026-10-16, TODO/155)
Using ZS greatly reduces the data per event, but **the per-ch threshold table (pedestal) depends on the electronics settings**.
If the table and the settings drift apart, you either discard signal or read all the noise.

### Procedure
1. Take a **pedestal run**: `triggerMode periodically` + `readout full`, about 150 events (Save in the Parameters tab → run/start).
   ZS is **OFF** (read all cells with full). Leave peaking / gain at the values used for physics.
2. Make the table and generate params with ZS (on either the Mac or ELITPC; `calib` from `cargo build --release` is needed):
   ```
   tools/scan/zs_params.sh --ped-run /data/tpcdaq/run0123 --label 502ns \
       --base ~/test/scan/base.json --out ~/test/scan/zs_502ns.json
   ```
   **Check by eye** that `base peakingTime_ns / gain` in the summary is the same as the settings at the time of the pedestal run (if not, fix the base and rerun).
   Use `--keep-fpn` when you want to always read the FPN (for common-mode subtraction).
3. Apply the generated JSON in the Parameters tab (or scan.py) → physics run. The number of exceptions is shown in the status bar as `exceptions N`
   (equal to the number of ch. Write "ZS threshold table <label>" in the logbook).
4. Put the table file in `[system] ped_table` (used by the downstream reconstruction of ZS data). **If you change peaking / gain, retake the table,
   update `ped_table`, and `daq_down.sh` → `daq_up.sh`** (without a restart the old table remains).

### How to read the counters
- ZS items appear in the decoder / root_sink / monitor counters (names as implemented, SPEC v1.49):
  decoder = `frames_type1` / `frames_type2` / `compact_size_mismatch` in run_stop.counters (ZS is type1 only; type2 and mismatch being 0 is correct),
  root_sink = `pevent_zs_frames_table` / `pevent_zs_frames_no_table` / `pevent_table_missing_channels` in the end JSON,
  monitor = `uvwZsFragmentsRestored` / `uvwZsFragmentsNoTable` / `uvwTableMissingChannels` in the status JSON and the stop log
  (paths that make it visible per run = close line / status / run_stop are TODO/159). **If `pevent_zs_frames_no_table` or `uvwZsFragmentsNoTable` is not 0** =
  ZS frames are arriving but no table has been loaded (`ped_table` unset or wrong path). Meanwhile ped is a substitute value, and pulse height and charge cannot be trusted.
  Fix the table and `daq_down/up`; write "no ZS table" in the logbook for that run.
- If `ped_source` in the metrics JSON of `run_metrics.C` is `cells_1_20` and `zs_suspected` is set, ZS data is being analyzed without a table
  (reanalyze with `metrics_for_run.sh --ped <table>`).
- To stop ZS, set `zeroSuppression.enabled` in the base back to false and Save (the threshold exceptions may remain, but give the reason for `exceptions N`).
