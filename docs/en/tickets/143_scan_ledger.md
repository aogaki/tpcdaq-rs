## 2. Generating tool (Sonnet implementer, ordered)
`tools/scan/ledger.py` (standard library only, in the style of `scan.py` / `test_scan.py`):
- Input: the result JSON of scan.py (`scan_<name>_<date>.json`: `name`, `points[] {i, knobs, run, params_id, frames, elapsed_s, stop_reason}`) and the metrics directory (`run%04d_metrics.json` = output of run_metrics.C). Optionally the graw byte count (if `--run-root DIR` is given, output the sum of `DIR/run%04d/*.graw` ÷ events in kB/event).
- Output: one Markdown table (standard output). Columns = point / run / knobs (only the difference from base, `k=v` joined with `, `) / events / kB/event (if available) / first·last hit median / width / hit ch / total charge (M) / saturated events (%) / clip start·end (edge, %) / ok / length median·IQR / track charge (M) / dEdx median·IQR / dip RMS. Runs without metrics get "—". Runs whose tracks are null are not dropped either.
- Usage: `python3 tools/scan/ledger.py SCAN_JSON --metrics DIR [--run-root DIR] [--title "S10 …"]`. If `--title` is given, a `## <title>` heading is put at the top.
- Test `tools/scan/test_ledger.py`: with a synthetic scan JSON + metrics JSON for 3 runs (one without metrics, one with tracks null) + a fake graw (known byte count), fix the table rows, columns and number formats (decimals, % notation, M notation). `python3 -m unittest tools/scan/test_ledger.py`. Regression of the existing 8 tests of `test_scan.py`.
- One section in the README.
