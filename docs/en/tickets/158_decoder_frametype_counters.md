## 0. Rationale
ZS arrives as frameType 1 (measured: run 133 31.8 kB, 165–169 65 kB. Compact is fixed at 278.8 kB). The compact path at `src/decode.rs:290-306` assumes the order of full readout (ch 0..67 -> next bucket) and restores (ch, bucket) with a cursor, so if the FW emitted compact + ZS it would **silently misplace** data. There is currently no per-frameType counter, so this cannot be checked from run_stop.

## Specification
- Add `frames_type1` / `frames_type2` to the decoder counters (per run, not reset by rearm — same treatment as `acquisition_restarts`) -> metrics -> `run_stop.counters` (Counters of `src/logbook.rs`, `src/controller/status.rs`; the UI shows two numbers).
- A frameType 2 frame whose number of items does not match the expected `68 × nAget × 512` family -> count in `compact_size_mismatch` + WARN once (do not drop the frame, do not make it an Error).
- Tests: counters with the existing frameType 1 / 2 fixtures in `decode.rs`, `compact_size_mismatch` with a synthetic compact of mismatched size, round trip of logbook / status. `cargo fmt && cargo clippy --tests -- -D warnings && cargo test`.
