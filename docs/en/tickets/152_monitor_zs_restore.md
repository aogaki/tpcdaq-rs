## 0. Problem
In `src/reco/mod.rs:232-290` the ped = mean of cells 1..20 (no FPN), and the baseline of the UI Event Display = mean of cells 0..24 of 0x02 (SPEC §5.4 v1.18, `ui/src/app/monitor/root-histo.ts:309`). In ZS data the missing cells are 0, so ped ≈ 0 -> every strip is a hit, and the baseline display is 0 too.

## 1. Specification
1. `MonitorParams.ped_table: Option<PathBuf>` (`config.system.ped_table`, the same key as 151). At startup read it with `calib::read_json::<PedestalTable>` (`src/calib/pedestal.rs`) and log the path / `meta.generated_at` / number of channels.
2. `DisplayConverter::with_pedestal_table(...)` (`src/monitor/display.rs`): precompute, for each (cobo, asad), `base[plane][strip] = Σ round(mean)` (over the strip channels of that AsAd, looked up with `geometry.lookup_ref`) and `round_mean[aget][raw_ch]`.
3. In `accumulate_uvw`, per fragment, the **ZS-like predicate** (same definition as 151: for a majority of the channels that have samples, the number of samples inside the ped window `PED_LO..=PED_HI` = 1..20 is < 20 — two passes: count, then accumulate). If ZS-like and a table exists, add `base` to all buckets of the strips of that AsAd, and add `(adc − round_mean)` for the samples that exist (i32, clamped to u16). = the same as filling the missing cells with round(mean) (consistent with section summation, identity for full data).
4. Non-ZS fragments / no table: as before. ZS-like without a table -> `zs_fragments_no_table` + WARN once. Counters `uvw_zs_fragments_restored / uvw_zs_fragments_no_table / uvw_table_missing_channels` go through `ConvertCounts` -> stop log + status JSON (`src/monitor/json.rs`).
5. `Reco`, `MM_PER_CELL`, the constants, and 0x03 (waveform, raw as is, 0) are unchanged.

## 2. Tests
- `display.rs`: (a) ZS fragment + table -> grid = restoration oracle (missing cell = round(mean), existing cells unchanged), strips with multiple sections (only one present -> `adc1 + round(mean2)`). (b) full + table -> identical to no table (exact thanks to integer rounding). (c) ZS, no table -> unchanged + counters. (d) `Reco::run` on the restored grid gives the same `strip_hits` as non-ZS (compare by applying a ZS cut to the synthetic track in `src/reco/tests.rs`).
- `tests/monitor_e2e.rs`: the configuration key is wired through. `tests/reco_macro_oracle.rs` unchanged. `cargo fmt && cargo clippy --tests -- -D warnings && cargo test`.
