## 0. Purpose and criteria
Using the 138 kernels (peaking 70 / 232 / 502 / 1014 ns, `all.mean_norm` of `~/test/scan/kernel2/run010{3,5,7,9}_kernel.json`, t = −40…+300 cells @ 40 ns), **deconvolve with regularisation** the α waveforms (runs 84–88 of 137 / 140, 25 MHz) and produce the following as numbers.
1. **Charge recovery**: whether the deconvolved charge of run 84 at 232 ns **comes into the same ratio (1 : 2.3 : 5.2 → 1 : 1 : 1)** as the charges at 502 ns (run 85/87) and 1014 ns (run 86) (= whether the ballistic deficit can be removed). If so, an operation with "no saturation & charge collected" by short shaping + deconvolution holds.
2. **Time width**: the pulse width (FWHM) after deconvolution, and the spread of peak times between strips (a proxy for z resolution).
3. **Noise amplification**: by what factor the RMS of the ped region (ch without hits) changes before and after deconvolution. Tabulate for 3 regularisation parameters.
4. Confirm that the wiggle (137) **remains** (remaining is correct — the conclusion of 138).

## 1. Implementation (`tools/scan/deconv.C` + `test_deconv.C`, ROOT macros, C++17. Include `run_metrics.C` to share the preprocessing)
- Kernel: read `mean_norm` from the JSON, a discrete kernel h[k] of length 341 with the peak placed at t = 0. The −40 before the peak is included in the kernel (the rise of the shaping). The constant offset of the kernel tail (≈ +1 %) is made 0 by subtracting the mean of +50…+300.
- Method: **frequency-domain Wiener type** (KISS, FFT is ROOT's `TVirtualFFT`): `X̂(f) = Y(f) · H*(f) / (|H(f)|² + λ)`, λ = 3 points of noise/signal ratio (e.g. 1e-3 / 1e-2 / 1e-1 × max|H|²). The waveform is 512 cells after FPN + ped subtraction, zero-padded at the ends to 1024 points.
- Output (JSON): per run and per λ, the median of the charge (sum) of hit ch, the median FWHM, the RMS of the ped region (before / after), the spread of peak time across ch. PNG: before/after overlay of 1 ch of 1 event + a table of charge ratios.
- Entry point: `int deconv(const char* raw, const char* kernelJson, const char* outJson, double lambda, const char* outPng = nullptr, int maxEvents = 0)`.

## 2. Tests
- Synthetic: convolve a known "true current" (rectangle + exponential tail) with the kernel and add noise; check that with small λ it returns to the true current (charge within 1 %, exactly back at λ = 0), and that with larger λ the noise RMS decreases and the width broadens (monotonic).
- Kernel loading (JSON keys, peak position = index 40), offset removal, 1 for a missing file.
- Measured red → green, and regression of the existing 3 (`test_run_metrics` 88, `test_pulser_kernel` 237, `test_drift_end` 88).

### Answers
1. **Charge recovery**: the deconvolved charge ratio is 232 : 502 : 1014 = **1 : 1.05 : 1.21** (before: 1 : 2.24 : 5.0). This agrees with the pulser (same input charge) peak gain ratio 1 : 1.05 : 1.17 (138). → **The sample-sum charge collects the input charge completely at every peaking** (area of a linear system = input charge × sum of the kernel. Kernel sums 9.7 / 20.7 / 40.3 × gain difference = 1 : 2.24 : 4.8 ≈ measured). **The statement of 137 "the current 232 ns integrates only part of the signal" is wrong** (it has been tested, so a correction note was added to archive/137). What changes with peaking is the **peak height** (saturation rate 0.3 → 4.8 → 34 %, threshold crossing of weak strips 121 → 128 → 147 ch) and the time width, not the total charge. The ballistic deficit affects only the peak.
2. **Time width**: with the shaping removed, the FWHM is 13.7 / 14.6 / 18.7 cells (0.55 / 0.58 / 0.75 µs, λ 1e-3) = **converges to the detector-intrinsic width (spread of the charge arrival)**. At 1014 ns it is 43 → 19 cells, less than half. The spread of peak time across ch (≈ 7 cells) is set by the track inclination and is not changed by deconvolution.
3. **Noise amplification**: the S/N proxy is ×0.4–0.5 at λ 1e-3 and ×0.86 at 1e-1 (the recovery of the width weakens). The operating value is **1e-2** (charge −1 %, width close to 1e-3, S/N ×0.6–0.7).
4. The wiggle was not measured in this ticket (the conclusion of 138 = it cannot be removed with the electronics kernel, is sufficient).

### Ruling (Fable)
- **The "short shaping + deconvolution" operation is not adopted**: the charge is collected as a sum at every peaking, so the gain from deconvolution is only in the time structure. E (overnight) is, as in 140, **502 ns × 240 fC** (compatible detection efficiency of weak strips and saturation 0.7 %).
- Deconvolution is kept as an **offline option** (when looking at the z structure with 1014 ns data, λ 1e-2). Whether it can be used to separate overlapping pulses in 130 (multiple tracks) will be judged then.
- Tool: `tools/scan/deconv.C` (`4e25dba`). The Mac has no FFTW (O(N²) DFT, slow), ELITPC has FFTW (30 s/run).
