## 0. Prerequisites (already implemented — do not build new server features)
- `PUT /api/params {token, params}` (SPEC §3.3 / §8.1, 409 while Running). The shape of the params JSON is `tests/fixtures/params/params_roundtrip.json` (schema `tpcdaq-params/1`, `template`, 12 `knobs`, `exceptions`, `note`).
  The current setting on ELITPC is `/srv/tpcdaq/params/current.json` (template `configure-elinp.xcfg`, 25 MHz, triggerDelay 1500, readout partial).
- `POST /api/control/acquire {operator, passphrase}` → token, `POST /api/run/start {token, comment}` → `{run, phase, params_id, notes}`, `POST /api/run/stop {token}`, `POST /api/control/release {token}`.
- `GET /api/status`: `phase`, `run.run`, `components[].metrics`. For mini (1 AsAd), **the receiver's `frames` = number of events** (1 frame = 1 event). The decoder's `malformed` / `acquisition_restarts`, `notes`.
- Recording is automatic: in the ledger, `run_start.params = {id, sha256, exceptions}`, `run_stop.counters`. A scan is **self-recording**, so the driver's JSON only needs to be an index of "run number ↔ setting point".
- Safety boundary (SPEC §11): only GET parameters are varied. **Do not touch HV / LV / gas** (do not write code in the driver that calls any power-related API).

## 1. What to build — `tools/scan/scan.py` (Python 3 standard library only, runs on ELITPC. No `requests` — use `urllib`)
- Input: scan definition YAML or JSON (**use JSON** — the standard library suffices. Example `tools/scan/examples/trigger_delay.json`):
  ```json
  {"name": "tdelay_2026-10-14", "base": "/srv/tpcdaq/params/current.json",
   "stop": {"events": 1500, "max_s": 600},
   "points": [{"knobs": {"triggerDelay": 1000}}, {"knobs": {"triggerDelay": 1250}}, {"knobs": {"triggerDelay": 1500}},
              {"knobs": {"triggerDelay": 1750}}, {"knobs": {"triggerDelay": 2000}}]}
  ```
  Read the `base` params JSON, **overwrite** the `knobs` of each point (keys not given stay as they are), and make `note` = `scan <name> point <i>: <diff of knobs>`. `exceptions` stay as in base.
- Flow (each point): check that the phase is Idle → `PUT /api/params` → `run/start` (comment = same as note) → read `GET /api/status` every 2 s, and `run/stop` when receiver `frames` ≥ `stop.events` **or** elapsed ≥ `stop.max_s` → record the reply and the status after `run_stop` → next point.
  At the end, **PUT the base params again** (restore the current setting — mandatory. If it fails, display it loudly).
- Stop conditions (not silently): PUT / start / stop is not 2xx, a warning other than `notes` being non-empty, decoder `malformed > 0`, `acquisition_restarts > 0`, frames do not grow for 30 s (rate 0), `late_fragments` > 0 if it appears in status. When stopping, print the reason, and exit 2 **after stopping the run and restoring base**.
- Token: acquire once at the start (`operator` is an argument, default `scan`), release at the end. The passphrase is `--passphrase-file` (by default read `passphrase = "…"` from `/opt/tpcdaq/daq.toml` — same as the existing scripts). **Do not write the passphrase to logs or JSON**.
- Output: `<out_dir>/scan_<name>.json` — `{name, started, base_sha256, points: [{i, knobs, params_id, run, started_ts, stopped_ts, frames, elapsed_s, stop_reply, status_at_stop (excerpt of counters), ok}]}`. Rewrite it after each point (it survives a crash midway). One progress line per point on stdout.
- `--dry-run`: print the PUT body and the procedure and send nothing. `--resume <json>`: skip points already done (ok=true).
