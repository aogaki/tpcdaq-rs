## 0. Questions
- How does the z determination precision of a single hit σ_z (= peak-time precision × v_drift) change with peaking (70 / 232 / 502 / 1014 ns)? A longer shaping raises S/N but blunts the rise. It cannot be known without measuring.
- Whether to "use the width as the error": the measured width is intrinsic width ⊕ shaping width (139: subtracting the kernel in quadrature gives an intrinsic width ≈ 14.5 cells, independent of peaking). If the width is used, it is the intrinsic width with the kernel removed. Compare with the measured z residual and decide which is appropriate as the error.

## 1. Inputs (ELITPC `~/test/scan/metrics/`, outputs of the user's macros. **The macros are only read, not changed**)
- TTree `uvw` of `run00NN_uvw.root`: strip hits per event `slView` (0/1/2 = U/V/W), `slZ` (z [mm] = t_peak × v_drift), `slS` (strip coordinate within the view [mm]), `slQ` (charge), `width[3]`, `nhits[3]`.
- TTree `tracks` of `run00NN_tracks.root`: `ok`, the two ends of the line `xStart..zEnd` (step 4 of `macros/makeTracks.C`: fitting z = z0 + tanθ·l to all hits. l is the coordinate along the track in the XY plane).
- Runs: peaking scan 83 (70 ns) / 84 (232) / 85 (502) / 86 (1014), same HV 250 × 3, 120 fC. In addition 123–127 (different HV).

## 2. What to build: `tools/scan/hit_residuals.C` + `test_hit_residuals.C`
- Entry point `int hit_residuals(const char* uvwRoot, const char* tracksRoot, const char* outJson, const char* outPng = nullptr, int maxEvents = 0)`.
- Per event (only ok == 1): reconstruct the XY direction and z(l) from the line (start→end), and for each hit **obtain the hit's l from the view's projection** (same geometry as makeTracks.C: read the view's direction vector and the definition of `slS` from the macros and use the same formula — the formula is not written in the work order because the macros are authoritative. Before implementing, quote the relevant part of the macros in the report). Residual r = slZ − (z0 + tanθ·l).
- Output (JSON): run, events, hits, the **RMS and robust σ (1.4826 × MAD)** of the residual per view and overall, the median of the residual (bias), the robust σ per charge quartile (S/N dependence), the median of `width` (width[3] of uvw). PNG: residual histogram (per view) + residual vs charge.
- Note: exclude hits at the two ends of the track (outside the 2–98 % quantile of l) (the charge drop at the ends is not a matter of width). The line itself is fitted including those hits (autocorrelation), so σ is slightly biased toward the lower side — state this in the report. The number of hits is large (≥ 20), so the correction is small.
- Test: fix the expected values of RMS / MAD / median / quantiles with synthetic uvw/tracks (a known line + Gaussian residuals of known σ + end hits + an ok=0 event), 1 for a missing file. Regression of the existing tests (`test_run_metrics` 88 / `test_pulser_kernel` 237 / `test_drift_end` 88 / `test_deconv` 133).

## 3. Application and judgement (main session)
On runs 83–86, a table of σ_z (robust) vs peaking → compare with the intrinsic width of 139 (14.5 cells × 40 ns × v_drift) → decide between "error = intrinsic width" and "error = measured σ_z (peaking dependent)". Separate the S/N dependence with different HV (123–127).

### Answers
1. **The z precision of a single hit is σ_z ≈ 0.2 mm ≈ 1 cell** (232–502 ns). At 1014 ns it is 0.25–0.31 mm (+30–60 %), at 70 ns 0.27 (S/N shortage, especially the weak strips Q1 0.34). It hardly depends on the HV (gain) in the range 250 → 230 V (0.20–0.22 at 502 ns).
2. **"Using the width as the error" overestimates by more than a factor of 10.** Against an intrinsic width of 14.5 cells = 2.8 mm and a raw width of 39–106 cells = 7–20 mm, the measured σ_z is 0.2 mm. If used as the error, it should be **the measured σ_z (the values in the table per peaking)**. If one insists on deriving it from the width, it would take the form of the intrinsic width with the kernel removed divided by √(effective number of samples), but the straightforward approach is to use the measured value.
3. The RMS is 2–5 times the robust σ = heavy tails (outliers from multiple tracks, noise, saturated ch). The track fit must be made robust (MAD / outlier rejection), otherwise it is dragged by the widths. Note that the RMS at 502 ns (≈ 1.0) is larger than at 1014 (0.3–0.6) (the way the outliers appear differs. Unexplained, material for 130).
4. Note: the residual is relative to a line fitted with the same hits, so σ is slightly small (≈ 1 % at ≈ 50 hits per view). The edge cut uses makeTracks's 2–98 % charge quantile as it is (asymmetric but without effect on the robust σ — the implementer's remark recorded).
