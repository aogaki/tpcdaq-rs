## Facts
- `caengeco2020` 1.16.1 was installed with snap **devmode** (`install.sh` runs `snap install --devmode`). Plugs: home / network / opengl / unity7 / x11 (the config-geco of `personal-files` is not connected). Because of devmode, `/dev/ttyACM0` (dialout, daq is a member) and `/var/lock` can be used from inside the snap (confirmed).
- The DT1415ET is USB CDC = `/dev/ttyACM0` (`/dev/serial/by-id/usb-CAEN_SPA_DT1415_HV_Power_Supply-if00`). slowctl also opens and closes the same port every 1 s.

## Pitfalls and solutions
1. **The window does not open with "Authorization required, but no authorization protocol specified"** — GNOME is a Wayland session, and the snap's x11 cannot use the XWayland cookie (`/run/user/1000/.mutter-Xwaylandauth.*`). Solution: `xhost +SI:localuser:daq` (allowed only for daq on the same machine = effectively not loosening anything). Made permanent: `~/.config/autostart/xhost-local.desktop` (`Exec=xhost +SI:localuser:daq`, desktop-file-validate OK, from the next login). sudo is irrelevant (the app was running in daq's session).
2. **"Unable to connect / Some errors occurred"** — two things overlapped:
   - slowctl was still running (= GECO was started without shutting down the DAQ) and contended for `/dev/ttyACM0`. Even after closing GECO, `/dev/shm/CAENV_LCK_0_0` (CAEN's link 0 lock) remains.
   - **Writing `/dev/ttyACM0` in the Port field fails**: libcaenhvwrapper builds the path with `/dev/%s`, so it becomes `/dev//dev/ttyACM0`. **Write `ttyACM0`**. This is the real cause (the symptom is that GECO does not even touch the port = does not show in lsof, no lock either).
   - The type is **SMART HV** (the identification name of the DT1415ET, manual p.16), connection **VCP USB**, 9600 / 8 / 1 / none, **LBus Address 0**. Selecting a DT55xx-family type (saved key `DTHV_`) goes looking for raw USB and fails. The unit is in REMOTE.
3. Tools for isolation: `lsof /dev/ttyACM0` (who holds it), a read-only probe (`$CMD:MON,CH:8,PAR:VMON` → `#CMD:OK,VAL:…`, /tmp/hvprobe_ro.py), `~/snap/caengeco2020/x1/.config/CAEN/App.conf` (the connection settings saved by GECO), `strings libcaenhvwrapper.so`. strace cannot be attached to processes inside the snap (ptrace_scope 1, snap-confine is setuid).

## Operation (user's decision)
When setting the HV: **`daq_down.sh` → set in GECO → close GECO → `daq_up.sh`**. The new values remain in the next run's run_start.slow. Do not bring the DAQ up with GECO left open.

## Operations that could not be performed
sudo (snap install, apt) and GECO operation were done by the user. Tracing with strace is impossible (above).
