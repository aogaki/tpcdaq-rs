## 0. Inputs and location
- root-sink's raw tree (SPEC §6.7, `<run>_raw.root`): `eventId/i`, `eventTime/l`, `adc[4][68][512]/S` (raw ADC, FPN included, unread = −1). mini = 1 AsAd (ch 0..67, FPN = {11,22,45,56}).
- The user's macros (repository `macros/`, read-only. The copy on ELITPC is `~/test/ana/ana_107/`, with `channel_map.csv` bundled): `analyzeUVW(rawFile, pressureMbar)` → `_uvw.root` (utree: `qview[3]`, `width[3]`, `nhits[3]`, `slView/slZ/slS/slQ`), `makeTracks(uvwFile)` → `_tracks.root` (ttree: `ok`, `xStart..zEnd`, `dirX/Y/Z`, `length`, `charge`, `dEdx`, `*F`). Verified to work on ELITPC (ROOT 6.40 / gcc 15) in 107.
  Note: analyzeUVW's time → z assumes 25 MHz (the current setting is 25 MHz, so consistent. Runs ≤ 56 are 100 MHz).

## 1. What to build — `tools/scan/run_metrics.C` (ROOT macro, C++17, `root -b -q 'run_metrics.C("<raw.root>","<out.json>",<pressure>)'`) + a thin shell script `tools/scan/metrics_for_run.sh <run_dir> <out_dir>`
- **From raw (independent of the macros, all events)**:
  - For each signal ch (excluding FPN) in one event: pedestal = mean of cells 1..20, hit = a ch that has a cell above ped + 35 ADC (same constants as src/reco: ADC_THRESHOLD 35, ped cells 1..20).
  - **Band position**: the first hit cell of the event (min over all ch) and the last (max). Give the median and the 10/90 % points of the distribution (c of 080 B-4 = window − delay − L).
  - **Window-edge clip rate**: the fraction of events whose first hit is at cell ≤ 2 or whose last is at ≥ 509 (front and back separately).
  - **Saturation rate**: the fraction of hit cells with ADC == 4095, and the fraction of events containing at least one saturated ch.
  - **Pulse width**: the median over hit ch of the number of consecutive cells above threshold (the metric for the peakingTime scan).
  - The median of **number of hit ch per event**, and the median of total charge (sum above threshold after ped subtraction).
  - Number of events, the first and last `eventTime` (→ rate).
- **From tracks (if present)**: `metrics_for_run.sh` calls the macros to create `_uvw.root` / `_tracks.root` if they are missing (`root -b -q 'analyzeUVW.C("<raw>",<p>)'` → `makeTracks.C`. The macros path is the argument `--macros <dir>`, default `~/test/ana/ana_107`). run_metrics.C reads `_tracks.root` if it exists:
  - ok fraction, median and IQR of `length`, median and IQR of `charge` and `dEdx`, RMS of the dip angle `atan2(dirZ, sqrt(dirX²+dirY²))`, RMS of φ.
- Output JSON (one file per run, fixed keys. Missing values are null): `{run, raw_file, events, rate_hz, first_hit_cell: {median, p10, p90}, last_hit_cell: {...}, clip_front, clip_back, saturated_sample_frac, saturated_event_frac, pulse_width_cells_median, hit_channels_median, charge_median, tracks: {n, ok_frac, length: {median, iqr}, charge: {median, iqr}, dEdx: {median, iqr}, dip_rms_deg, phi_rms_deg} | null}`.
- It is not a hot path, but it scans 1,500 events × 4×68×512, so read ROOT's array branches directly with `SetBranchAddress` (a TTreeReader array is also fine). Target within 10 s per run.

## 5. Addendum (2026-10-14, found on real data run0076 — Fable): bring the hit definition in line with the macros / src/reco convention
- Measured: `hit_channels_median 250` (there are 256 signal ch), `last_hit_cell 511 / clip_back 1.0`, `charge_median 1.6e6`.
- Cause (raw waveforms): on all ch the baseline **rises monotonically by 20–40 ADC** within the window (cell 1 → 511: 480 → 511, 442 → 477, 358 → 387) + noise ±10. It is common-mode, so it can be subtracted with the FPN ch.
- Fix:
  1. **Subtract the common-mode with FPN**: for each AGET make the cell-wise mean of the 4 FPN ch {11,22,45,56} and subtract it from each signal ch of the same AGET. Then ped = cells 1..20, threshold 35. Exclude ch whose cells are all 0 under partial readout.
  2. **Lower limit on charge**: only ch whose sum of ped-subtracted values within peak ±5 cells is > 2000 count as hits (macros STRIP_Q_MIN, the same constant as the halo cut in `src/reco/mod.rs`; cite the source in a comment).
  3. **Band position is the peak cell**: first / last = min / max of the peak cells of the hit ch. For clipping, both "peak at cell ≤ 5 / ≥ 506" and "above-threshold region reaches the edge" (`clip_front_peak` / `clip_front_edge`, likewise for back).
  4. **Fold the orientation**: φ is the RMS of the axial angle folded at 180° (`phi_axial_rms_deg`), dip is the RMS of |dip| (`dip_abs_rms_deg`). The head/tail from makeTracks is a coin toss.
  5. Keep the `pressure` argument.
- Test: put a baseline slope common to all ch (up to +40, the same on FPN) into the synthetic raw; before the fix all ch are hits and last is 511 (red), after the fix only the hits that were placed. A small pulse with charge < 2000 does not become a hit. Even when tracks with φ flipped by 180° are mixed in, the axial RMS does not change.

- **Real data (runs 76, 78–82, `--pressure 91`, macros = `~/test/ana/ana_107`)**: 3.4 s per run (including macros). The table is in archive/135 and the triggerDelay section below.
- Remaining weakness: `clip_back_edge` is 0.65–0.74 in all runs = the **jump at cell 511** remains after FPN subtraction and exceeds the threshold (the peak-based `clip_back_peak` is 0). Either exclude cell 511 from the edge-type metrics or use only the peak-type ones (next time this is touched).

- **The band position is strictly linear in delay**: moving by 250 × 10 ns = 2.5 µs moves it by 62.5 cells (× 40 ns = 2.5 µs). `first_median = 508 − delay/4`.
- Applying 080 B-4's formula c = (window − delay − L)/40 ns gives **L ≈ (512 − 508) × 40 ns ≈ 0.16 µs** (trigger latency = first arrival of charge → CoBo trigger). This puts a number on the homework of 084 #3 (plausible as the delay of the CFD + NIM stage).
- **Optimum**: the condition of placing the start of the band (p10) at least 10 cells from the window edge, `p10 = 493 − delay/4 ≥ 10` → **delay ≤ 1930**. The current 1500 throws away 5.4 µs (134 cells) before the trigger. **1750–1850 is recommended** (at 1750 p10 = 55, 17.6 µs after the trigger ≈ 85 mm @ 0.48 cm/µs). At 2000 the start is cut off in 15 % of events and the ok fraction and the length drop (= `clip_front_peak` and `ok_frac` work as judgement metrics for automation).
- Time width of a track: the median of last − first ≈ 23 cells (0.9 µs), ≈ 70 cells at p90 (2.8 µs ≈ 13 mm).
