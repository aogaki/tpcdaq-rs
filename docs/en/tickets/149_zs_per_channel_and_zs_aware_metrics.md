## 0. Aim
In 141 the CoBo ZS (uniform 600) worked end to end and gave 14.8 kB/event (1/19 of full). Since the ped varies from 364 to 548 ADC by channel, setting **threshold = ped + k·σ per channel** gives the same compression without losing small signals. On the analysis side, ped / FPN subtraction does not hold for ZS data (suppressed cells are 0, and the FPN is suppressed too), so a path that uses an external pedestal table is needed.

## 1. Generator tool `tools/scan/zs_exceptions.py` (standard library only, Sonnet)
- Input: the JSON of `calib pedestal` (`channels[] {asad, aget, ch, mean, rms, is_fpn}`, ELITPC `~/test/scan/calib/pedestal_502ns.json`), k (default 5), lower limit `--min-above` (default 20 ADC).
- Output: the `exceptions` array of the params (JSON, to standard output or `--out`): for each channel (FPN included) `{"knob": "zeroSuppression.threshold", "at": {"asad": a, "aget": g, "ch": c}, "value": round(mean + max(k*rms, min_above))}` (the key of `at` is `ch`, per the schema). Clipped to the range [0, 4095]. With `--merge BASE.json`, it inserts `exceptions` into the base params and outputs a params JSON with `zeroSuppression.enabled = true`.
- Test `tools/scan/test_zs_exceptions.py` (unittest): with a synthetic pedestal of 3 channels, fix the values, rounding, clipping, min_above, the handling of FPN, and the result of merge.
- Note: match the shape of `exceptions[].at` (`{asad, aget, channel}`) and the knob name to `docs/PARAMS_KNOBS_ja.md` §4-3 / §6 and the schema in `src/params/` (read them to confirm, and quote them in the report).

## 2. ZS support in `run_metrics.C` (Opus-level but bound by the work order -> Sonnet)
- New optional argument `const char* pedJson = nullptr` (`run_metrics(raw, outJson, pressure, tracksRoot?, pedJson)` — keep compatibility with existing calls. Add `--ped FILE` to `metrics_for_run.sh`).
- If pedJson is given: the ped is the `mean` of the table (per channel), **no FPN common-mode subtraction** (because the FPN is suppressed in ZS), and the hit threshold stays 35 ADC (after ped subtraction) as before. If not given, behave as before.
- Detection of ZS data: if, in one event, the fraction of signal channels whose cells 1..20 are all 0 exceeds 50 % and there is no pedJson, **emit a WARNING once** (do not silently use a wrong ped). Add `ped_source: "cells_1_20" | "table"` and `zs_suspected: bool` to the JSON.
- Add to `test_run_metrics.C`: with a synthetic ZS raw (cells below threshold set to 0), with pedJson the charge and hit channels agree with the non-ZS case (±5 %), and without pedJson `zs_suspected` is true and a WARNING is emitted. The existing 88 checks are unchanged. Regression: `test_pulser_kernel` 237 / `test_drift_end` 89 / `test_deconv` 133 / `test_hit_residuals` 145 (all include run_metrics.C).

## 3. Application (main session)
pedestal_502ns.json -> exceptions (k = 5) -> params (B + ZS on) -> 1 run (1,500 events) -> metrics with `metrics_for_run.sh --ped`, kB/event. Compare with the uniform 600 of 141 (run 121) and full (run 130).

- **The tool works**: with `run_metrics --ped`, the charge of ZS data (2.02 M vs 2.09 M = −3 %), the hit channels, and the saturation agree with non-ZS. The data volume is **1/8.8** of full (larger than the 1/19 of uniform 600 because the threshold is lower than 600 on many channels (median 504) and keeps small signals = as intended).
- **※ The user's macros (analyzeUVW / makeTracks) break on ZS data**: length 126 mm (84 is correct), σ_z 0.73 mm (0.21 is correct). Presumably because the macros take the ped from inside the waveform (cells suppressed by ZS are 0). **The macros belong to the user and are not touched** -> to use ZS in production, the macros need a path that reads the pedestal table (`calib/pedestal_*.json`) (user's decision). Until then, operation is without ZS (full, 279 kB/event).
- The 141 observation that "the charge of run 121 with uniform 600 looked twice as large" was due to the ped not being subtracted, a kind of problem that `--ped` resolves (confirmed).
