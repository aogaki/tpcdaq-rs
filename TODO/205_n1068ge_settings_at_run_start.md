# 205 — トリガ(CAEN N1068GE)の設定を run の開始時に読んでログブックに残す

**Status: TODO(設計は Fable キュー — 置き場所と経路)**(2026-11-04 起票 Opus。出どころ = 131 B-3 の「次」⑤、ユーザー案「run 開始時に slowctl で読んで記録、ポーリングはしない」)

## 動機
2026-11-03 から事象のトリガは N1068GE の OR(131 B-3)。閾値・極性・フィルタ・OR の有効 ch は**モジュールの中にだけ**あり、今は run の記録(params・ログブック)に何も残らない。run 215 と 208 の差(ヒット有り + 28 %、ヒット無し 1.7 → 13.8 /h — 131)は閾値しだいで、後から「その run の閾値はいくつだったか」が読めないと比べられない。

## 機器の事実(131 B-3、2026-11-03 実機で確認)
- ASCII over TCP 23: `$BD:00,CMD:MON,CH:x,PAR:...\r` → 応答 1 行。**1 接続に 1 コマンド**(続けて送ると 2 つ目以降が返らない)。既定 IP 192.168.0.1/24、board address 0。
- 読む値(ch 0–15、`MON`): POL、SHAPE、CGAIN、FGAIN、PZADJ、PUR、TINT、TDIFF、TGAIN、THR、OR の有効、CFD 出力の遅延、MUX、ORWDT。ボード: BDNAME、BDFREL、SERNUM。
- **絶対にしないこと: `MUX` を `CH:16` で送る**(コマンド口が固まり、NIM クレートの再起動まで戻らない。設定は残る)。読み出しも `SET` は一切しない(読むだけ)。
- CFD の遅延(J1 ジャンパ、全 ch 40 ns)はソフトから見えない → 記録は「固定値の注記」で。

## 決めること(Fable)
1. 経路: (a) slowctl の新しいドライバ(読むのは run 開始の合図のときだけ、周期の読み出しはしない)→ 既存の `run_start.slow`(SPEC §9.2 v1.31、`src/controller/mod.rs` の `slow_snapshot`)に載せる (b) controller が run 開始時に直接読む (c) params(current.json)側に「トリガ」の節を作り、PUT のたびに機器から読み直して照合する。推し(Opus)= (a)。slowctl はすでに機器ごとの接続と失敗の可視化を持っていて、controller に TCP 23 の作法を持ち込まずに済む。ただし slowctl は今は周期の読み出しだけで、「run 開始の合図で 1 回読む」口が無い。
2. 読めなかったとき: run は止めない(トリガの記録は派生情報)。`run_start` に `trigger: null` と理由を残し、WARN を出す(silent にしない)。
3. 機器のネットワークの置き場所: 今の接続(USB-C Ethernet でユーザーの Mac と 1 対 1 だったもの)から、ELITPC から届く場所へ移す必要がある(ユーザーの作業)。IP の衝突: N1168 も既定 192.168.0.1。

## 受け入れ(案)
- 偽の N1068 を相手に、1 接続 1 コマンドの作法と、`CH:16` の MUX を送らないことをテストで縛る。
- 実機: run の開始で全 16 ch の THR などがログブックの `run_start` に入り、131 の記録(THR 250 mV、POL 1、TINT 1、TDIFF 1、OR 全 ch)と一致する。
