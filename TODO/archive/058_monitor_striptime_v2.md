# 058 — モニタ StripTime 2D の改善(転置 / イベント毎リセット / ベースライン減算)

**Status: COMPLETED**(2026-08-16 — 結果は末尾。起票・改訂・完了同日)
**仕様**: SPEC §5.2 / §6.2(モニタ集計)。**保存系(PEventTPC / FPN ペデスタル算法)には
一切触らない** — これは表示専用の変更(保存と可視化の分離 = 絶対ルール)。
**発注先想定**: implementer/**Opus**(C++ 集計 + Angular 表示の両側)

## ユーザー要求(2026-08-16。**同日改訂**: Event Display が既に per-event 2D で
あることをユーザーが確認 → 「イベント毎リセット」は Event Display 側の改善に読み替え)

1. **1D Charge 系は完璧 — 無変更**(堆積型のまま)。
2. **軸の転置(2D 両方)**: TPCReco の慣習に合わせ **縦(Y)= strip 番号、
   横(X)= time bucket** にする(現状は逆)。**StripTime 2D と Event Display の両方**。
3. **per-event ビューは既存の Event Display が担う** — StripTime 2D の堆積リセットは
   **やらない**(Σ ADC マップとして残す。死にストリップ・ホットチャンネルの診断用)。
4. **ベースライン減算(表示専用)は Event Display に適用**: 各イベント・各ストリップ毎に
   **最初の 25 点(time cell 0..24)の平均**をベースラインとし、全データ点から引く。
   **負値はそのまま**(0 に切り上げない)。TPCReco の表示流儀。
   Event Display の注記「生 ADC・減算なし」も実態に合わせて更新。
5. **デモのデータレートは 1 Hz くらい**(elitpc プロファイルの送出既定を
   1 event/s = 4 frames/s に変更。`TPCDAQ_DEMO_RATE_HZ` の上書きは維持)。

## 根拠の追記(2026-08-16 ユーザー — SPEC 追補に載せる文言の元)

表示専用に限定する理由はルール遵守だけではない: **①オフライン解析側は自前で改めて
ベースラインを計算する**(ここで引いた値に依存しない)**②「先頭 25 サンプルの平均」は
大抵うまくいくという経験則の決め打ちにすぎない**。経験則をデータに焼き込むと後段の
解析の自由度を奪うので、データ変更は好ましくない — モニタの見やすさのためだけの補正。

## 実装指針

- **転置は表示側(UI)で**やるのが KISS(ワイヤ形式・集計の格子は不変で、描画の
  軸割り当てだけ入れ替える)。ただし実装調査でワイヤ側を変える方が素直と判明したら
  報告して戻ること。
- **ベースライン減算は Event Display の表示経路**: `0x02 Uvw` メッセージは生 ADC の
  まま(ワイヤ不変が第一候補)、**UI 側で strip 毎に先頭 25 cell の平均を引く**のが
  最小変更。負値を扱えるカラースケールにすること。UI 計算が重い・不自然と判明したら
  集計側(root_sink)で引いて負値対応の値型で送る案を報告して戻る。
- 1D(Charge/ChargeMax/イベント数)と Waveform タブは無変更。
- ヘッダの注記(「x 軸は…4095 が常に見える」)が 2D には合わなくなるので、
  2D 側の説明文だけ実態に合わせて直す(1D の記述は不変)。
- モニタ系なので**ドロップ許容・counted** の性質は不変。スナップショット頻度も不変。

## 結果(2026-08-16 — implementer/Opus 実装、発注側(Fable)レビュー PASS)

### 実装(UI 3 ファイルのみ — root_sink・Rust・保存系は 1 バイトも変更なし)

- **転置**: `buildHisto2d` / `uvwPanelSpec` が描画時に x↔y を入れ替え(縦 = strip /
  横 = time bucket)。ワイヤ(§5.3/§10.2)と monitor.root は不変。StripTime と
  Event Display の両タブ同一の向き。
- **ベースライン減算(Event Display のみ、表示専用)**: `stripBaseline` = strip 毎に
  先頭 25 cell の平均(`min(25, nBuckets)` の防御つき — 実機は常に 512 で影響なし)。
  負値保持。読み出しの無い strip は baseline 0 → 不変(JSROOT は値 0 を描かないので
  「未読が黒く沈む」ことがない)。
- タブ注記文を実態へ更新。デモ elitpc の送出既定 20 → 4 frames/s(= 1 event/s)。
- 改訂(リセット中止)前に着手していた root_sink 側は checkout で撤回済みを確認。
