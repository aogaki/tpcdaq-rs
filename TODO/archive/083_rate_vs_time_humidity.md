## 仮説と判別(第 2 弾 — 完了、2026-09-17)

- 仮説 A(ユーザー): **ガス湿度**(H₂O、あるいは O₂)による電子付着 → 信号が小さくなり、外部トリガ閾値を超えるイベントが減る。
  → 判別量 = **イベントあたりの電荷(qview 合計)の時間変化**: 付着なら電荷スペクトルが時間とともに低側へずれ、レート減少は
  閾値で切られた分に一致する。湿度計(Michell Easidew)/ O₂ 計(NTRON)の読みがあれば相関を取る。
- 仮説 B(Fable、消去すべき対抗仮説): **²¹²Pb(T½ 10.64 h)の減衰** — 溶接痕の ²³²Th 系列から出た ²²⁰Rn(thoron、56 s)の
  娘 ²¹²Pb が壁・カソードにプレートアウトしていて、ガス交換/流通が始まって供給が止まり 10.6 h で減る(α は ²¹²Bi/²¹²Po)。
  観測の 12.1 ± 0.8 h は 10.6 h と 2σ 以内。→ 判別: 電荷スペクトルは**変わらず**、数だけ減る。定数 0.014 Hz = 溶接痕直接の α。
- 手順: `graw2root.C+`(09-15、実行中)→ `analyzeUVW.C`(`_uvw.root`: eventId, qview[3])→ 時間(ヘッダ走査の eventId → 秒)と
  結合して「電荷の中央値 vs 時間」「前半/後半の電荷スペクトル」を出す(新 macro `chargeVsTime.C` か rateVsTime に追加)。
- ユーザーに聞くこと: ①run 中のガスは流通か静置か、切替の時刻 ②露点計・O₂ 計の読み(時刻付き)③再起動(1.7 h)で何を変えたか
  ④トリガ源(NIM チェーン)の入力は何の信号か(閾値の効き方に直結)。

## 結果(第 2 弾: 電荷 vs 時間、2026-09-17、Mac)

- 手順: `graw2root.C+`(09-15、10,027 events → 1.28 GB raw.root)→ `analyzeUVW.C+`(macros/ から実行、`channel_map.csv` 必須。
  定数は 1200 V / 100 mbar の既定のまま — 電荷合計には効かない)→ **`chargeVsTime.C`(新規)** で eventId 順に結合、1 h bin。
- **判別結果**: レートが 0.137 → 0.025 Hz(×1/5.5)に落ちる 45 h の間、**イベント電荷(Σqview)の中央値は 4.5e6 → 5.0e6 ADC
  (+11 %)、16–84 % 帯も動かず、ヒット数中央値 ≈ 18k で一定**。前半 1/4 と後半 1/4 の電荷スペクトルはほぼ重なる(後半が
  わずかに高側)。→ **仮説 A(湿度/O₂ の電子付着で信号が落ちて閾値割れ)は否定**: 付着なら電荷が下がるはずで、逆に上がって
  いる。上がった分(+11 %)は系が乾いていく(付着が減る)か圧・ゲインの変化と読めるが、レート減少とは逆向きで説明にならない。
- **残るのは仮説 B(数だけ減る = 放射性の減衰)**: T½ = 12.1 ± 0.8 h は ²¹²Pb(10.64 h)と整合、定数 0.014 Hz が溶接痕の
  ²³²Th 直接分。再起動前セグメント(0–1.7 h)は電荷中央値 3.2e6 / ヒット 16.5k と別条件(設定違い)。
- 含意: (a) 「バックグラウンド」の大半は溶接痕の thoron 娘のプレートアウト(²¹²Pb)で、**ガス交換・流通の履歴で大きく変わる**
  — 静置後の run 開始直後が最も高い。物理 run の前に十分な流通時間(> 1 日)を置くか、run 中の減衰を織り込む。
  (b) 湿度は少なくともこの run ではレートに効いていない(電荷 +11 % の緩い上昇は別途、露点計の記録と照合する価値あり)。

## 追記(2026-09-17、ユーザー回答と再起動の証拠)

- ユーザー回答: ①run 中ガスは流通。その前に**線源を取り出すため圧を上げ → 線源除去 → 圧を下げ → 流通**。②露点計の記録は
  残っているはず(ガスエンジニア待ち)。③1.7 h の再起動は本人にも謎。④トリガ = **GEM フォイルの HV からフィルタボックスで
  取った信号**(= GEM ゲインに比例する信号の閾値。付着や圧でゲインが変わるとレートに直接効く経路)。
- **再起動の証拠(データ)**: ファイル 0000 の frame #173 に **topology frame(frameType 7、12 B)**があり、その直前 #172 が
  eventIdx 171 / t = 5554.7 s(1.54 h)、直後 #174 が eventIdx 0 / t = 3.06 s。topology frame は DAQ start のたびに書かれる
  (graw2root.C 冒頭・067)ので、**1.54 h の時点で DAQ(CoBo run)が stop → start されている**(GetController は同じファイルに
  追記し続けるので run 名は変わらない)。自然なグリッチではなく操作。
- 再起動前セグメント(172 events、0.031 Hz、電荷中央値 3.2e6 / 後段 4.5e6)は圧が高かった時期(圧下げの途中 → GEM ゲイン低 →
  GEM 信号トリガの閾値を超えにくい)と読むのが自然。再起動後は圧が落ち着き、以後は ²¹²Pb の減衰(T½ 12.1 h)+ 溶接痕の定数。
- 物理像の修正: ²¹²Pb の供給源は溶接痕だけでなく**取り出した ²²⁸Th 線源そのものの thoron**(線源在室中にプレートアウト)が
  主。線源除去後に 10.6 h で減り、溶接痕分(0.014 Hz)に落ち着く。→ 線源を使った直後の物理 run は 1〜2 日待つ。
- GEM 信号トリガの含意: ゲインの緩い上昇(+11 %)はレートを**上げる**向きなので、観測の減少とは逆 — 湿度・ゲインでは説明不能を
  補強。露点記録が来たら電荷中央値の +11 % との相関を見る(083 の続きは新票で)。

## 追記 2(2026-09-17、「初期は線源が置かれているような絵になるか」— ユーザー質問)

- 方法: `makeTracks.C+`(09-15、10,027 events)→ 前半(再起動後 2–10 h、²¹²Pb 優勢、3,067 本)と後半(> 30 h、溶接痕優勢、
  1,887 本)で、上端/下端の z、|dip|、飛跡長、上端・下端の (x,y) を比較(`reference/_spike/rate_0915/earlyLate.{C,png}`)。
- 結果: **両者はほぼ同じ分布**。上端 z・下端 z・飛跡長は重なり、|dip| は前半がわずかに小さい(中央値 ≈ 22° vs 25°)。
  (x,y) は両方ともパッド面全体に一様 + 縁に集中(外から入るトラック)。窓上端(上位 10 %)に届く割合は前半 7.0 % / 後半 12.2 %
  で、**前半にカソード面から降ってくる成分が増えている様子は無い**。
- 結論: **視野内に「線源が置かれている」ような局在は見えない**。²¹²Pb は特定の点ではなく内面全体(壁・ケージ)に付いていて、
  溶接痕と同じ「どこからでも」の絵になっている。ただし視野は z で 87 mm(analyzeUVW の既定 v_drift)× パッド 106 mm で、
  カソード面(200 mm)と線源ポート付近は視野外 — そこに局在があっても見えない。
- 副次観測: 下端 z が 20–27 mm に集中(前後半とも)= GEM 信号トリガの時刻に対する窓の固定位置。ここは 080 B-4 の delay 設計と同根。
