## 追補 — 発注側の裁定(2026-08-14。実装からのエスカレーション 2 件に回答)

実装側の指摘 3 点を**発注側が実コードで裏取りして確認済み**:
`src/receiver.rs` の `'accept: loop`(1 接続ずつ・内側 read ループ)/ `fake_ecc.cpp` の

### 裁定①(fake-ECC の「幻の CoBo」)= **harness の artifact。production は変更しない**

- 実機では **CoBo が張る 1 本の TCP がそのままデータリンク**であり、そこにデータが流れる。
  `fake_ecc` の connect は **CoBo の身代わり**(listen-before-start の負性テストを成立させるため)。
  E2E-C では `graw_replay` が CoBo 役なので、**CoBo が 2 台いる**状態 = テスト構成の artifact。
- **採る手**: `fake_ecc` に **データリンクを張らないモード**(例 `--no-data-link` / 環境変数)を足し、
  E2E-C/D はそれを使う。**接続してから close する案は不可** —— receiver は
  `Ok(0)` を run 境界として **EOS を送る**(`send_end_of_stream`)ので run が空で閉じる。
- **`TPCDAQ_P3_STUB_ECC` は削除**(ECC 段だけ偽物にする二重機構を残さない)。
  E2E-C は **controller → ecc-bridge → Ice → fake-ECC servant を実配線のまま**通す
  (= §12-7 の「全通し」の主張を保つ)。「データリンクが実際に張れること」の証明は
  016/017 の listen-before-start 負性テストが既に持っている。
- **ファイル所有権を拡張**: `tools/ecc_bridge/fake_ecc.cpp`(+ 必要なら同 Makefile)。
  **fake_ecc はテストダブルであって production ではない**。再ビルドは `make -j`。
  既存の 016/017 テスト(実リンクを張る前提)を**壊さないこと**(新モードは既定 OFF)。

### 裁定②(E2E-F)= **030 から外し、別ユニット [033](033_error_path_semantics.md) へ移す**
