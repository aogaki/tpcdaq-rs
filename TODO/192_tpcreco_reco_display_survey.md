## 1. TPCReco の 4 つのやり方
### (a) 人のクリック(GUI、HIGS 2022 の解析の本体)
- `GUI/src/MarkersManager.cpp`: 1 つの面でクリック → その時刻に全面へ縦の補助線(`drawFixedTimeLines`)。2 つ目の面で同じ時刻(x はクリック 1 回目に固定)の位置をクリック → 2 面の位置から xy を出し、3 つ目の面の位置を計算して自動で描く(`getMissingYCoordinate` → `Cartesian2posUVW`)。= 2 クリックで 3D の 1 点。
- **最初の点 = 共通の頂点、以後の点 = 各トラックの終点**(`updateSegments`: 2 本目以降の線分の始点は 1 本目の始点)。星形(頂点から N 本)。
- `TrackBuilder::getSegment2DCollectionFromGUI`(`Reconstruction/src/TrackBuilder.cpp:375`): 面ごとの 2D 線分から 3D 線分を作るだけで、**当てはめをしない**(`myFittedTrack = aTrackCandidate`)。`HistoManager::drawRecoHistos` の「reco disabled for clicking campaign」= HIGS の再構成はクリック作業。
- 表示(`GUI/src/HistoManager.cpp`): UVW の投影は **mm 単位**(z [mm] × ストリップ位置 [mm])。3D 線分を各面へ投影して **線幅 4 の破線**(`drawTrack3DProjectionTimeStrip`、クリック中の線は線幅 3)で重ね、始点 = 白丸・終点 = 黒丸。4 枚目 = XY の線分、または**トラックに沿った電荷(charge/mm vs d)**に α・¹²C の dE/dx 模型と飛程からのエネルギー(`drawChargeAlongTrack3D`)。自動ズームあり(`makeAutozoom`: 最大値の 10 % を超えるビンの範囲 ± 10 ビン + 幅の 10 %、縦横比はそろえない)。
  → ユーザーの言う「見やすいが線が太すぎて下のデータが見えない」はこの線幅 3–4 の破線を、データと同じ 1 枚に重ねていること。

### (b) 自動(現行): 直線 1 本 + 「α と ¹²C が一直線」の仮説
- `TrackBuilder::reconstruct`(:203): 面ごとのヒット(`RecHitBuilder::makeCleanCluster` = 最大値から広げるクラスタ、閾値 = 最大の 80 % の核和)→ 投影から直線 1 本の種(`buildSegment3D`)→ 当てはめ(`fitTrack3D`: 方向 → xy の位置 → z の位置の順)→ 長ければ `fitEventHypothesis`(:885): 直線に沿った電荷の分布に α と ¹²C のブラッグ曲線(拡散でぼかす、`dEdxFitter`)を当てはめ、頂点の位置・両方の飛程・向きを決めて 2 本に割る。
- 損失(`DataFormats/src/TrackSegment2D.cpp:186` `getHitDistanceLoss`): 面ごとに、ヒットから**投影した直線**(端で切らない)までの距離の 2 乗を電荷で重み付けした平均、20 mm より遠いヒットは数えない。**3D の点を作らず、模型を各面へ投影して面ごとのヒットと比べる**。
- Hough 変換は今の版ではコメントアウト。**γ ビームの 2 体(ほぼ背中合わせ)専用**で、¹⁶O(n,α)¹³C(開き角 ≈ 133–180°、実測 100–110° の事象もある)や 3α には使えない。

### (c) 旧版(higs_04、2022): Hough + 折れ線
- 面ごとの Hough 変換(電荷重み、最大の 5 % 以上、`nPeaks = 1`)で 2D の種 → 3D。`fitTrackNodesStartEnd`: トラックを**節点をつないだ折れ線**として全節点の座標を一度に当てはめ、合いの悪い区間を割って折れ点を足す(`splitWorseChi2Segment`)。曲がった 1 本向けで、星形ではない。

### (d) 順方向の模型による N 本の当てはめ(Mikolaj Cwiok 2023、`Reconstruction/examples/testStripResponseFitter.cxx`、本流には未統合の例)
- パラメータ = ADC の全体倍率 + **共通の頂点 (x, y, z) + トラックごとの終点 (x, y, z)**(1–3 本)。仮説(粒子の種類の並び、例 {α, ¹²C}・{α, α, α})は外から与える。
- 模型の描き方(`fillFitHistogramsInMM`): 各トラックについて、長さ → `IonRangeCalculator` でエネルギー → ブラッグ曲線(MeV/mm)。トラックに沿って 10 点/mm で電荷を置き、`StripResponseCalculator::addCharge`(σ_xy・σ_z のガウス拡散 + AGET の peaking time の整形、ストリップ・時刻の近傍に配る)で U・V・W の mm 画像を描く。
- χ²(`getChi2`)= Σ(データ − 模型)² / σ_noise²(σ_noise = 7 ADC / cell)を 3 面の全ビンで。罰則項(運動量保存 LAB / CMS、α・¹²C の長さの範囲)は (1 + Σ) で掛ける。
- 最小化 = Minuit2 / Fumili2、**初期値は人のクリック**、各座標は初期値 ± 7 mm、ADC 倍率は ×1/10–×10、段階的に固定・解放。
- 表示(`DrawFitResults`): 3 列(U・V・W)× 3 段 = **実データ / 当てはめた模型 / 残差(模型 − データ)+ χ²/ndf**。トラックは**線幅 2 の実線**、頂点 = マゼンタの ○ + 十字、終点 = トラックごとの色の ○(赤・緑・青)。データの段は線で隠さない。
- 例 3・5・6 の記述: HIGS 2022(130 mbar)の 2 本・3 本の事象をクリックを初期値に当てはめ、自動 RECO と人の RECO を並べて比べている。

### 付随
- `StripResponseCalculator`(`Reconstruction/src/StripResponseCalculator.cpp`、1,033 行): 点状の電荷 → 拡散(σ_xy, σ_z)+ peaking time → UVW の生 / mm 画像。モンテカルロの `TPCDigitizerSRC` もこれを使う = **シミュレーションのデジタイザと当てはめの模型が同じもの**。
- `IonRangeCalculator`(`Utilities/src/IonRangeCalculator.cpp`): SRIM の飛程・ブラッグ曲線、CO2 250 mbar・20 °C 基準を密度で換算(198 mbar に使える)。イオンは陽子・α・¹²C だけ(¹⁴C は ¹²C の表の仮置き)。**¹³C・⁹Be の表は無い**。
- モンテカルロの反応生成器(`MonteCarlo/EventGenerator`)は**光子入射の運動学を焼き込み**(`Reaction::GetKinematics(gammaMom, …)`)。反応は C12_ALPHA・C13_ALPHA・3α(民主的 / ⁸Be 経由)・粒子銃。中性子入射は無い。

## 2. 私たちの点の集合が辛い理由
- 1 つの時刻セルで、3 面それぞれが見るのは「その高さの電荷の 1 次元の射影」。3 本の 1 次元の射影から 2 次元の分布は一意に戻らない(戻るのは重心だけ)。点の集合は、1 セルに点が 1 つ(急な飛跡)のときだけきれいに出る。読み出し面に平らな部分・同じ時刻に複数の腕・短い腕では、重心の 1 点になるか、組み合わせのゴーストになる(191 の試作 1–3 版で実際に見た)。
- event 244(3α): ¹²C(n,n')3α のしきい値は E_n ≈ 7.9 MeV(Q = −7.275 MeV)。PuBe の上端 11 MeV でも 3 つの α に分ける余りは ≲ 3 MeV → 各 α は数 mm〜1 cm で、**拡散の足跡(7–9 mm)と同じ大きさ**。どの見せ方でもぼける。分けられるのは、拡散を模型に入れて当てはめる (d) のやり方だけ。
- TPCReco は 3D の点を作らない。模型(3D 線分)→ 各面へ投影 → 面のデータと比べる。曖昧さは「どの模型が 3 面を同時に説明するか」に置き換わり、組み合わせの問題が消える。

## 3. 提案(実装はユーザーの判断の後)
1. **表示の安い改善(先にやる価値が大きい)**: UVW を mm(z [mm] × ストリップ位置 [mm])で、**ヒットの範囲に自動ズーム**し、**縦横の mm をそろえる**(角度が見たまま正しい)。244 は今パネルの ≈ 3 % × 6 % にしか描かれていない → ズームだけで ≈ 15 倍に広がる。下段の点の集合は、急で長い 1 本の確認用に格下げ(または外す)。
2. **仮説の見せ方**: 仮説(人の入力でも当てはめでも)があるときは (d) と同じ 3 段 = データ / 模型 / 残差。線は細く(1–2 px)、頂点と終点は小さな印。**データの段には線を重ねない**(重ねる版は別の段)。腕ごとにトラックに沿った電荷(ブラッグの形で止まる端と粒子の種類が分かる)。
3. **再構成の芯 = (d) の順方向の当てはめ**(頂点 + N 本の終点、腕ごとの粒子の種類)。仮説 {α, ¹³C}・{α, ⁹Be}・{α, α, α}・{反跳 1 本}・{α 1 本} を当てはめ、χ² で選ぶ。¹⁶O(n,α)¹³C の運動学(E_n)は当てはめた頂点・終点から出る。
   - mini に要るもの: **v_drift の較正**(E/p = 0.40 は表の外挿 — z の目盛りが開き角に直接効く、173)、198 mbar の σ_T・σ_L(147 の測定)、AGET の peaking time と応答の核(138)、**¹³C・⁹Be の SRIM 表**、重イオンの電離の不足(クエンチング)、雑音 σ(ペデスタル)。
4. **ビーム実験の自動化**: 人のクリックの代わりの初期値が要る。候補 = 面ごとの Hough(複数の山)、急な部分は 191 の点の集合、ML の回帰(頂点・終点)。初期値 → (d) の当てはめで精密化 → χ² で仮説を選ぶ。**ML(176)は同じ順方向の模型(デジタイザ)で作ったシミュレーションで学習**し、実データでの当てはめの残差が「シミュレーションと実データが合っているか」の検査になる(176 の失敗の典型 1 への対策)。= 1 つの順方向の模型が、ML の学習データ・精密な当てはめ・模型の検証の 3 役を兼ねる。
5. **どこで作るか(要判断)**: TPCReco は改変しない(CLAUDE.md)。選択肢 = (i) TPCReco をそのまま動かす(mini のジオメトリ .dat、GET ライブラリで .graw を読む — Mac でのビルドは未確認)、(ii) 自前で小さく作り、TPCReco の `StripResponseCalculator` をオラクルにして数本の飛跡で照合(C++ 版をオラクルにする流儀)。Opus の推し = (ii)、置き場所は 176 の別プロジェクトと同じ判断(順方向の模型をデジタイザと共有するため)。表示の改善 1 は tpcdaq-rs の `macros/drawUVW.C` のままでよい。

## Fable 所見(2026-11-02)

**結論を先に**: 芯は (d) の「順方向の模型を strip × cell の画像に描いて χ² で比べる」で正しい。ただし Mikolaj の fitter をそのまま目指すのではなく、**N = 1(α 1 本、頭尻つき)から自前で小さく作る**。置き場は `macros/`(今の解析連鎖と同じ場所)。v_drift の較正は選別・表示・当てはめの**前提ではない**が、E_n と開き角を数字で言う前には要る。選別は「頂点が内側 + 電荷の並び」で今日から作れ、効率は **run 208(線源なし)を背景の物差し**にして測る。100–110° は物理より先に**測り方の artifact を疑う**。

### 1. 順方向の N 本当てはめは芯として正しいか — 正しい。ただし削る
- 正しい理由は §2 のとおり(3 面の 1 次元射影から 2 次元は戻らない。模型 → 射影 → 比較なら組み合わせ問題が消える)。点の集合(191)は「急で長い 1 本」の確認用に格下げでよい。
- **削るもの(KISS)**:
  - 運動量保存の罰則項・CMS ブースト — Mikolaj の fitter は γ ビームのエネルギー既知が前提。PuBe(連続)でも中性子ビームでも E_n は未知なので使えない。入れない。
  - ¹³C・⁹Be の SRIM 表 — 反跳は ≲ 1 cm = 拡散の足跡(7–9 mm)以下で、ブラッグの形は原理的に見えない。**反跳は「頂点に置く点状〜短い線分 + 自由な電荷」の 1 腕**で足りる。表が要るのは α だけ(TPCReco の `range_corr_thr_1keV_alpha_*` を reference から実行時に読む。または NIST ASTAR — stoppedAlphas.C が既に使っている)。
  - ADC の全体倍率を自由パラメータにしない — 貫通飛跡の q / mm(173 で時間ごとに追っている)で run ごとに固定。
  - Minuit の段階的固定・解放の儀式 — まず粗い格子 + ROOT の Minuit2 1 回で足りるか見る(模型が軽いので格子が安い)。
- **足すもの**: ① 整形は理想の AGET でなく **138 の実測核**(502 ns、12.5 MHz に換算)② **飽和(4095 で切る)を模型に入れる**(明るい反跳は飽和する — 下の §5)③ χ² は mm でなく **strip × cell の生の格子**で取る(mm は見せ方の問題。格子で取れば 1 cell = 1 サンプルで σ_noise の意味がはっきりする)。
- **期待値を正しく**: 順方向の当てはめでも、244 のような「各 α ≲ 足跡」の 3α は腕の向きは決まらない。決まるのは「3α の仮説 vs 塊 1 つの仮説の χ² の差」まで。192 §2 の「分けられるのは (d) だけ」は「χ² で仮説を比べられるのは (d) だけ」と読み替える。
- **当てはめは v_drift を決められない**(066 の厳密縮退: 直線は (strip, cell) 空間でも直線。z を伸ばしても χ² は同じ)。z の目盛りは**外から**入れる(§3)。

### 2. 作るか使うか — 自前(ii)。TPCReco は照合の相手
- `testStripResponseFitter` をそのまま回すのは不利: 初期値が人のクリック前提で自動化できない、罰則項が γ ビーム前提、GET ライブラリで .graw を読む経路、`GeometryTPC.cpp:508` のスタック overflow(Mac で頻発、066 で既知)。「Mac でのビルド未確認」は言い過ぎで、066 で 11 .cpp を無改変で直リンクできることと、χ² の格子には遅いことまで分かっている。**`StripResponseCalculator` は数本の合成飛跡の画像を照合するオラクル**としてだけ使う(066 の `response.hpp` が 1D で数値照合済み — その流儀の 2D 版)。
- **置き場 = `tpcdaq-rs/macros/`**(`fitProngs.C` + `test_fitProngs.C`、drawUVW と同じ流儀: 純関数 + exit code = 失敗数)。理由: raw.root → analyzeUVW → makeTracks → drawUVW の連鎖・`channel_map.csv`・実データ・テストの型がすべてここにあり、ユーザーが今ここで作業している。1,500 行を超える / コンパイル速度が要る段になったら `tools/reco/`(C++17 + ROOT、root_sink と同じ閉じ込め)へ移す。移すのは安い。**始めない方が高い**。minitpc-analysis(Python、PyROOT なし)には今は持ち込まない(読み取り専用の方針とも合う)。
- **176 との関係を訂正**: 「1 つの順方向の模型が ML の学習データ・当てはめ・検証の 3 役」は言い過ぎ。tpcsim には既に Stage 2–4(Garfield++ ドリフト + AGET 整形)の**フル デジタイザ**がある。ここで作るのは**速い媒介変数モデル**(ブラッグ + ガウス拡散 + 実測核)で、役割は当てはめ。2 つのデジタイザが**同じ α に同じ画像を出すこと**が相互の検査になる(176 §3-2 の関門に 1 項目足す)。速いモデルを ML の学習データ生成に使うかは、フル チェーンが遅すぎると分かってから決める。

### 3. 2〜3 週間の順番(チケット案、受け入れ条件つき)
v_drift の扱いを先に決める: **較正は選別・表示・当てはめの前提にしない**。E/p = 0.40 は表(0.54–1.05)の外挿だが、CO2 のこの領域は電子が熱的で v ∝ E/p(147 で相対の線形性 ±6 % を実測済み)。外挿誤差は ≲ 10 % と見る(開き角に効くのは数度、133° に要る ×2.8 とは桁が違う)。**E_n・開き角を数字で出す前に絶対値を測る**。測り方 = **同じ 198 mbar / 1600 V / 12.5 MHz で α 線源(stoppedAlphas.C の既知の線)を 1 時間**: 止まった α の 3D 飛程 = √(Δxy² + (Δcell × mmPerCell)²) を既知のエネルギー(ASTAR)に合わせ、**mmPerCell を「傾き(dip 角)に対して飛程が一定になる値」で決める**。既存マクロで済む(「z-edge」= 陰極端の方法は、この窓(512 cell ≈ 120 mm < ドリフト 200 mm)では陰極が窓に入らないので**使えない**)。線源はチャンバーを開ける機会(湿度の件があるので中性子 run 中はやらない)に。

### 4. 当てはめの前の暫定選別 — 「頂点が内側」+「電荷の並び」
今日の数字が言っていること: 「両端内側」は 16 本中 2 本しか残さない(物理的に α ≈ 13 cm > 有感 10.6 cm なので当然)。超過は x の壁から出ていく飛跡にある。要るのは**頂点が内側**で、問題は**どちらの端が頂点か**を当てはめ無しで決めること。KISS の答え = 電荷の並び:
- 壁から入った α(背景 50 / h の本体): 壁側 = 低、内側 = ブラッグ(高)。**電荷が壁 → 内へ単調に増える**。
- 内で生まれて壁へ出る α: 内側の端 = 塊(高、反跳)または α の出だし(低)、壁側 = 途中で切れる(中)。**単調増加ではない**。
規則(makeTracks の直線に沿って 5 mm ごとの q / mm を取る):
1. 両端が内側(10 mm) → `contained`。
2. 片端が内側: 内側の端から 5 mm の q/mm = q_in、壁側 5 mm = q_wall、中央 = q_mid。`q_wall < q_mid < q_in` かつ q_in が最大 → `wall-alpha`(捨てる)。それ以外 → `vertex-in`(残す。壁が x か y かを理由コードに)。
3. ≤ 10 mm の塊(compact.C)→ `blob`(別クラス、残す)。
4. 191 のクラスタで、1 つの cell に ≥ 2 クラスタが 3 面とも ≥ 5 cell 続く → `multi` の印(切らない)。
5. **x 沿いの向きでは切らない**。それは測りたい結果(ビーム軸)であって選別条件ではない。変数として残す。
効率の測り方(16 本を信じない):
- **run 208 が背景の物差し**: 各クラスの率を 208 / 209 で並べ、超過 (209 − 208) とその Poisson 誤差。選別の良さ = 超過が有意で 208 の率が低いこと。16 本の残存率は**健全性の確認だけ**(落ちた事象は理由コードを見て規則を直すか、目の方が間違っていたかを 1 本ずつ判断)。
- **目の偽陽性率を測る**: 208 と 209 から各 300 事象を混ぜて番号を伏せ、ユーザーがもう一度選ぶ。208 から選んだ割合 = 目の偽陽性率。1 時間で済み、16 本の信用度が数字になる。

### 5. 100–110° の開き角 — 仮説の順と安い試験
1. **測り方の artifact(最有力)**: 5・27 の短い腕はどちらも「頂点から −z へ、非常に明るい(2,000–3,400 ADC/cell = 飽和の近く)」。191 の点は cell ごとに置くので、**点状の明るい電荷は、パルスが閾値 35 を超えている cell の数だけ同じ xy に点が並ぶ = z 方向の「腕」に見える**。明るいほど立ち上がりで閾値を早く切り(time walk → −z)、尾(イオンテール・リンギング、137/138)は長く残る(+z)。12 mm = 51 cell = 4 µs は 502 ns の核だけでは長いが、飽和 + 尾なら届く。→ 短い腕が反跳の「向き」ではなく「時間波形」なら、開き角は物理量ではない。**試験 = 195**(時間波形と核の重ね、飽和の数)。これが当たりなら、反跳の向きは足跡以下で決まらないと認める(¹³C の飛程 ≲ 1 cm なので、そもそも期待どおり)。
2. 三体の終状態: ¹²C(n,n')3α(E_n > 7.9 MeV)で 2 本の α が重なる、¹⁶O(n,n'α)¹²C(E_n > 7.6 MeV)。PuBe の上端 11 MeV で起きる。開き角は任意。試験 = 198 の {α + 塊} の χ² と塊の電荷(3α の重なりなら塊の電荷は α 1–2 本分で、反跳の飽和した塊より暗い)。
3. 二体で反跳が本物だが、向きが z 寄りで短く、1 の効果と混ざって角度が小さく出る。試験は 1 と同じ(時間幅を核で割った残りが空間の長さ)。
4. z の目盛り(v_drift): ×2.8 が要るので**棄却**(Opus の読みに同意)。196 の後に数度の補正として残るだけ。
5. 偶然の重なり: 0.03 Hz で無視。
